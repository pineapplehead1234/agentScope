# AgentScope 简历亮点

## 当前已实现可写

- 安全边界治理：基于 Electron Main / Preload / Renderer 三层架构，将 Pi SDK runtime、SessionManager、本地文件读取等能力收敛到 Main Process；Renderer 关闭 Node 能力，通过 `contextBridge` 仅暴露受控 IPC API，避免 React UI 直接接触 SDK、文件系统和 Shell 能力。
- Pi SDK Runtime 封装：在 Main Process 封装 `createAgentSessionRuntime`、`createAgentSessionServices`、`createAgentSessionFromServices` 和 `SessionManager.continueRecent`，将 SDK 初始化、session metadata、prompt/abort control 和 event subscription 与 Renderer 解耦。
- Session Replacement 管理：封装 `runtime.newSession()` 与 `runtime.switchSession(sessionPath)`，在 session replacement 成功后重绑 `runtime.session.subscribe()`，避免旧 session 事件继续推送到当前 Renderer timeline。
- Runtime State 可观测化：通过 typed IPC 暴露 `getState()`、`getMessages()` 和 `getSessionStats()` 的 serializable view，将 token/cost/context usage 等指标接入 Context Panel。
- Agent 事件归一化：将 Pi SDK `AgentSessionEvent` 转换为 Renderer 可消费的 `AgentRuntimeEvent` discriminated union，覆盖 agent start/settled、assistant text delta、tool execution start/end 等核心事件。
- 流式 UI 状态归并：设计 `AgentEventReducer`，将高频 `text_delta` 合并到稳定 assistant message view model，并用 `startTransition` 处理非紧急 timeline 更新，避免每个 raw delta 直接触发独立 UI item。
- Tool Timeline 建模：基于 SDK `toolCallId` 跟踪工具执行实例，解决重复 `read`/`grep`/`bash` 等同名工具调用造成的 React key 冲突和状态串扰问题。
- Workspace Session UI：实现 workspace 维度 session 分组展示，并将 persisted session data 与 selected session、expanded workspace paths 等 Renderer-only UI state 分离，支持后续 session refresh / replacement 场景。
- Markdown Preview 安全通道：通过 Main-side file preview service + Preload IPC 读取 workspace 内 markdown 文件，使用扩展名校验和 realpath containment 防止 Renderer 任意读取本地文件或通过 symlink/junction 逃逸 workspace。
- 可测试工程化：搭建 Electron + React + TypeScript + Vite + Tailwind + Vitest 项目骨架，覆盖 Main、Renderer、Shared 三层单测；当前 `npm test -- --run`、`npm run typecheck`、`npm run build` 均通过。

## 当前量化数据

- Electron process boundaries：3 层，Main / Preload / Renderer。
- Renderer Pi SDK imports：0。
- IPC channels：10 个，current session、markdown preview、prompt、abort、new session、switch session、state、messages、stats、agent event stream。
- Normalized event variants：5 类核心事件。
- Test coverage footprint：10 个 test files，34 条 tests。
